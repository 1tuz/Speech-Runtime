# Задание агенту: закрыть проверку Speech Runtime без нового интернет-ресёрча

Работай в `1tuz/Speech-Runtime`. Приложенный пакет содержит `RESEARCH.md`, `SOURCES.md`, `audio_sources.json`, `memory_probe_macos.c`, `proofs/`. Прочитай их. Это фактура и протокол, а не предложение заново выбирать модели.

Базовая версия аудита: `ff1c15b64f448c933f5a6fe285ac2169e508811e`. Если локальная версия новее, сначала сопоставь изменения с перечисленными дефектами; не возвращай уже исправленные ошибки.

**Интернет-поиск не выполнять.** Разрешены получение данных по явно указанным адресам и необходимые закреплённые зависимости. Недоступный URL отмечай blocked, не начинай новый поиск замен. Локальный анализ исходников/SDK, профилирование и реализация регрессий — обязательны.

Не добавляй новые ASR-модели, Qwen, диаризацию, GUI или универсальный фреймворк. Сохрани Swift-демон + Rust/wavo. Основные метрики: WER, задержка после фразы, реальная память.

## 1. Сначала исправь измеримость и проверяемые ошибки

- HTTP-парсер: отрицательный Content-Length воспроизведён в изолированной копии. Добавь строгие длины/лимиты до dispatch, тесты malformed headers без запуска против рабочего сервиса.
- `_no_starvation` сейчас проверяет ASR, не ожидание. Поменяй на queue/e2e и полноту завершений; отсутствие данных не PASS. Используй приложенный контрпример.
- Отмена: engine проверяет флаг только до run, а worker может отправить final удалённой сессии. Fake engine с барьером должен доказать отсутствие late final после cancel.
- Проверь carry неполного 256-сэмплового кадра перед end/flush.
- Все ошибки session_audio должны сохранять request id; enqueue-отказы должны быть видны клиенту как ошибки фраз.
- Убери сырой JSON из логирования запоздалых ответов. Canary-тест для timeout/cancel/crash.
- Не принимай факт наличия unit-тестов за доказательство интеграционной корректности.

## 2. Установи и устрани причину роста памяти

Факт отчёта: daemon RSS 12 → 380 МиБ при 16×; воркер почти стабилен. `/health` тоже вызывает worker.stats, поэтому прошлый опыт не отделил HTTP от IPC.

Выполни M0–M6 из RESEARCH: idle; HTTP без IPC; IPC к fake worker без HTTP; health с настоящим воркером без модели; ASR без демона; полный поток; медленный/отключившийся клиент.

Учитывай активные таймеры, pending, waiters, соединения, сессии, байты событий/PCM, FD и потоки. Снимай память снаружи без частых health-запросов самого профилировщика.

Сначала воспроизведение, затем один патч за раз. В WorkerClient:
- timer handle должен отменяться на ответ/ошибку/отмену/worker exit;
- CancellationError должен завершать таймер, не проваливаться в timeout;
- старый таймер ожидания не должен будить новую группу waiters;
- ограничить память глобально, не только числом events на сессию.

Профилирование Allocations/Memory Graph по командам пакета. Autoreleasepool и Network.framework — гипотезы, не установленная причина. Не переписывай сеть целиком на основании сильной ссылки в closure.

После нагрузки ждать 360 с и повторять серии на том же процессе. Различай утечку живых объектов, временные задачи и удержание страниц аллокатором. Итог — причина со стеком/счётчиком и воспроизведением до/после либо честное not established.

## 3. Добавь доступный учёт ANE

Собери и проверь `memory_probe_macos.c`. Используй rusage V6 для current neural/physical/resident counters; при недоступности V6 возвращай null и status. Для собственного процесса возможен TASK_VM_INFO без task_for_pid и без sudo. Сверь поля с локальным SDK.

Не складывай RSS, footprint и neural вслепую. Peak не должен падать после unload: нужен current. Проведи ANE-1 из пакета: fresh/load/first/100 repeats/vary lengths/unload/idle/worker exit/new worker/two models.

Не убивай coreaudiod/системные службы и не чисти глобальные кэши. Отдельно покажи границу видимости процессных счётчиков.

## 4. Реальный звук

Используй ровно шесть источников `audio_sources.json`:
- Флант Helm 5:51 и мониторинг DKP 57:10 — dev.
- Альфа-Банк Kubernetes 33:15, Сбер Kerberos/Istio 39:14, etcd-урок 29:33, AM Live 81:05 — heldout test и длительные прогоны.
Предлагаемые участки и URL уже заданы. Границы предварительные, до сравнения уточнить по звуку и заморозить. Не переносить соседние куски/зеркала/диктора между dev/test.

Сохранить естественные паузы; единоразово преобразовать в 16 кГц mono; записать хэши. Не проводить шумоподавление или silence trimming основного теста.

Автосубтитры/ASR-согласие — черновик. Для итогового WER нужен проверенный по аудио эталон. Если такой проверки выполнить нельзя, подготовь данные и пометь качество UNMEASURED; не заявляй ручную проверку, которой не было.

Проверить известную асимметрию нормализации филлеров. Версию и политику WER заморозить; старые показатели сохранить отдельно.

Сравнить одинаковые записи: файл без нашего VAD; отдельные размеченные фразы как диагностика; полный runtime 1×. Метрики: WER, ΔWER, потери/дубли у границ, очередь, ASR, доставка, p50/p95/max.

Добавить end_reason: silence/max_utterance/client_end. Различать акустический конец речи и last_voice по VAD. Использовать monotonic timestamps каждого блока; не подавать будущее аудио раньше времени.

Подбор параметров только на dev: min_silence 320/500/700, pre/post 200/300 мс. Итоговая test-проверка после заморозки.

## 5. Финальные проверки

60 минут реального времени, не 16×; 1 и 4 клиента; длинный batch рядом; две уже поддерживаемые модели при доступных весах; cancellation/crash в разных состояниях, новый worker generation, медленный клиент.

Проверить реальный client capture отдельно от подачи файла: sample rate, непрерывность PCM, права, смена устройства. Не объявлять файл 1× тестом микрофона.

Применяй заранее зафиксированные критерии раздела 6 RESEARCH. Важнее честный FAIL/UNMEASURED, чем зелёный отчёт. Не ослабляй пороги после получения результатов.

## 6. Результат

Нужны рабочие исправления, автоматические регрессии, воспроизводимые команды, обезличенные сырые метрики и короткий FINAL_VALIDATION.md:
- причина роста памяти и доказательство устранения;
- current/peak ANE и результат unload/exit;
- WER/ΔWER на реальном звуке, размер/статус эталонов;
- p95 после фразы при 1×, отдельно от ASR;
- границы устойчивой нагрузки и оставшиеся блокеры.

Веса, чужие аудиозаписи, транскрипты, токены и memory dumps в Git автоматически не публиковать. Коммить законченные проверенные этапы, push — по установленным правилам репозитория. Не повторяй исследования моделей, не подменяй недостающие результаты прогнозами.
