# ASR evaluation harness

Офлайн-скорер для сравнения транскрипций на одинаковых записях. Стандартная библиотека Python 3; моделей и инференса здесь нет. Фикстуры `fixtures/smoke` синтетические и проверяют только механику. [Dev sample корпуса](../corpus/README.md) содержит непроверенные транскрипты, а его лицензия неизвестна: это не тестовый эталон.

## Запуск

Из корня репозитория:

```bash
python3 -m unittest discover -s experiments/asr_eval/tests -p 'test_*.py'
python3 experiments/asr_eval/cli.py validate --dataset experiments/asr_eval/fixtures/smoke --terms experiments/asr_eval/terms.json
python3 experiments/asr_eval/cli.py score --dataset experiments/asr_eval/fixtures/smoke --split dev --hypotheses experiments/asr_eval/fixtures/smoke/hyp-runner-a.tsv --terms experiments/asr_eval/terms.json --json /tmp/asr-score.json
python3 experiments/asr_eval/cli.py compare --dataset experiments/asr_eval/fixtures/smoke --split dev --a experiments/asr_eval/fixtures/smoke/hyp-runner-a.tsv --b experiments/asr_eval/fixtures/smoke/hyp-runner-b.tsv --group-by recording_id --replications 1000 --seed 0 --json /tmp/asr-compare.json
```

`manifest.tsv`: путь аудио и референс через TAB; ID — имя файла без расширения. `metadata.jsonl`: одна строка на ID с `split` (`dev`/`test`), `speaker_id`, `recording_id` и остальными полями из [dataset.py](dataset.py). TSV гипотез: ID и текст через TAB. При смешанном наборе `--split` обязателен; скорер проверяет точное соответствие ID манифеста и метаданных и отсутствие пересечений дикторов и записей между выборками. Гипотезы должны содержать либо весь набор, либо ровно выбранный split; неизвестные и отсутствующие ID запрещены. Набор без метаданных получает `split: unknown`: использовать его как подтверждённый dev/test нельзя. Для `--report` split неизвестен; дублирующиеся и пустые ID запрещены.

## Метрики и версии

**`asr-eval-v2`, `norm-v2`, `term-v2` несовместимы с прежними результатами.** Пересчитайте все сравниваемые системы на одинаковых входах и версиях. JSON сохраняет версии скорера и нормализатора, версию и SHA-256 словаря, SHA-256 манифеста, метаданных и гипотез, выбранный split и параметры запуска. Хэши идентифицируют содержимое файлов, но не удостоверяют происхождение или лицензию аудио; версию и хэши аудио, модель, её ревизию, движок и параметры инференса необходимо сохранять вместе с результатом отдельно. Для импортированного отчёта сохраняется его SHA-256; идентичность корпуса и split не извлекаются автоматически.

- **WER**: сумма замен, удалений и вставок / число слов референса. **CER**: расстояние Левенштейна по символам нормализованных токенов без пробелов / число символов референса. Нулевой знаменатель — `null`; вставки при пустом референсе не исчезают из суммы ошибок корпуса.
- **`norm-v2`**: нижний регистр, пунктуация, `ё → е`, числа в слова и явные правила CI/CD. Ведущие нули дроби сохраняются: `1.05` отличается от `1.5`; версии и CIDR сохраняются. Знак минус в обычном WER трактуется как пунктуация: используйте отдельную командную метрику для флагов.
- **`term-v2`**: словарные совпадения ищутся в референсе и позиционном окне гипотезы. `TP` — однократно сопоставленные точная форма, транслитерация или эвристически распознанное искажение; `FN` — несопоставленные вхождения референса; `FP` — оставшиеся распознанные словарные формы в гипотезе. Precision = TP/(TP+FP), recall = TP/(TP+FN), F1 = 2TP/(2TP+FP+FN); нулевой знаменатель — `null`. Corpus-метрики считаются по сумме счётчиков. `recall_exact` включает латинские и прочие точные формы, `recall_any` совпадает с term recall. Искажения вне опоры на референс не выявляются как FP: это ограниченная эвристика, не полная оценка галлюцинаций.
- **Latin-form accuracy** = число точных латинских форм / (точные латинские формы + транслитерации терминов с латинской формой). Кириллические `wordform`, искажения и пропуски в знаменатель не входят. `case_accuracy` сравнивает регистр точных латинских попаданий с формами словаря.
- **`command-exact-v1`**: в метаданных сегмента укажите `"commands": ["kubectl get pods -n prod"]` для каждого размеченного вхождения. Команда должна присутствовать в референсе как непрерывная последовательность токенов, разделённых пробелами. `accuracy` — доля вхождений, найденных в гипотезе точно, с учётом регистра, пунктуации и `-n`; один токен нельзя использовать повторно. При отсутствии разметки — `null`. Это строгая проверка размеченных команд, а не семантическая эквивалентность shell-команд или полноценная оценка лишних команд; совпадение ищется во всём сегменте, поэтому требуется ручная проверка неоднозначных фраз.

Словарь терминов — кандидат; метрики находят формы в тексте, а не подтверждённые вручную позиции. Эвристика `corrupt`, транслитерации, возможные пересечения форм и трактовка команд требуют калибровки на независимой ручной разметке. До неё не используйте терминные и командные показатели как единственное основание выбора модели.

## Bootstrap

`compare` вычисляет парную разницу corpus WER A − B по одинаковым ID. По умолчанию повторно выбираются высказывания; `--group-by speaker_id` или `--group-by recording_id` выбирает целые группы вместе с результатами обеих систем. Нужно минимум две группы. Уровень группировки следует выбирать по структуре данных и фиксировать заранее; один уровень не устраняет одновременно зависимость по дикторам и встречам. Малое число групп ограничивает надёжность интервала. Percentile-интервал не является тестом нулевой гипотезы; старое поле `p_two_sided` удалено. Повторы с нулевым числом слов пропускаются и учитываются в `skipped_zero_words`; частые пропуски делают интервал ненадёжным. Seed и число повторов записываются в JSON.

## Ограничения

Пунктуация, латентность потоков, диаризация и VAD не измеряются этим стендом. `validate` проверяет структуру и предлагаемые пороги V8, а не качество референсов или юридические права. Для сравнения моделей нужны независимые проверенные транскрипты, вычитанный словарь, разметка команд и терминов, достаточный корпус и подтверждённые права. Инструкция по выбору метрик и экспериментов: [validation.md](../../docs/validation.md).

## Допуск корпуса к бенчмарку

`validate` — проверка структуры и предлагаемых порогов V8; для бенчмарка дополнительно обязательны `preflight` и режим `--benchmark`:

```bash
python3 experiments/asr_eval/cli.py preflight --dataset /path/to/corpus
python3 experiments/asr_eval/cli.py score --dataset /path/to/corpus --split dev --benchmark --hypotheses /path/to/hyp.tsv --terms experiments/asr_eval/terms.json --json /path/to/result.json
```

`compare` также принимает `--benchmark` и явный `--split`. Без `--benchmark` скоринг доступен для разработки, его результаты не являются подтверждённым бенчмарком. Для `--report` этот режим недоступен: у отчёта нет проверяемой связи с корпусом. Перед созданием гипотез выполните `preflight` отдельно; режим скоринга повторит проверку. Нулевой exit означает только прохождение механических правил, не подтверждение прав, точности транскриптов или достаточности выборки.

Манифест и JSONL описаны выше. Каждая запись `metadata.jsonl` дополнительно должна содержать:

| Поле | Значение для допуска |
|---|---|
| `source` | конкретный источник и идентификатор исходной записи/ревизии |
| `license` | известная лицензия или форма индивидуального разрешения |
| `rights_status` | `verified` после проверки прав человеком |
| `rights_evidence`, `rights_reviewer` | ссылка/идентификатор доказательства и имя или стабильный ID проверившего |
| `transcript_status`, `transcript_reviewer` | `verified` после прослушивания; имя или стабильный ID проверившего |
| `transcript_sha256` | SHA-256 UTF-8 текста референса из manifest после удаления пробелов по краям |
| `audio_sha256` | SHA-256 полного WAV-файла |

Человек заполняет поля и хранит документы о правах в подходящем защищённом месте, не публикуя персональные данные. Неизвестные лицензии и неподтверждённые разрешения нельзя маркировать `verified`. Preflight проверяет наличие указанных подтверждений и целостность, обе непустые выборки, соответствие ID, отсутствие пересечений дикторов/записей и идентичных файлов, локальный читаемый PCM WAV и длительность с допуском 0,05 с. Дубликаты с другой кодировкой, пересекающиеся фрагменты и связи разных источников требуют ручной проверки. `source` и текст свидетельств инструмент не проверяет по первоисточнику.

### Ручная разметка и заморозка

1. До разметки зафиксируйте происхождение, ревизию, право на использование аудио и дикторов; разделите по дикторам и записям на dev/test, проверив перекрытия фрагментов. Обращайте внимание на исходный split источника.
2. Прослушайте каждую запись; вручную подготовьте дословный текст. Сохраните оригинал и историю изменений отдельно от рабочего манифеста. Неясные слова помечайте для повторного прослушивания и исключайте из эталона до разрешения. Вывод ASR не заменяет проверку человеком.
3. В соответствии с [V8 §2.5](../../research/wave2/V8-eval-plan.md) приведите проверенный текст к принятой письменной форме с явными правилами терминов, чисел и пунктуации. Отмечайте каждое вхождение терминов и полные команды; для `commands` нужны точные строки, присутствующие в референсе. Сверьте с аудио и соберите разногласия.
4. Второй проверяющий независимо прослушивает спорные и выбранные контрольные фрагменты; зафиксируйте его решение и идентичность. Статус `verified` проставляется только после разрешения ошибок и проверки доказательств прав, затем вычисляются хэши. Preflight проверяет наличие одного reviewer для каждой категории, но не удостоверяет вторую проверку.
5. Настраивайте словарь, метрики и правила только на dev; сохраняйте версию и SHA-256 словаря. После калибровки заморозьте словарь, нормализацию, процедуру и test до запуска всех моделей. Изменение правил после просмотра test требует нового независимого test.

Синтетические golden cases в `tests/test_calibration_golden.py` и `test_calibration_terms.py` предназначены для проверки механики, не для измерения ASR. Реальный подтверждённый dev пока отсутствует. Исходный `test` Podlodka не используется для настройки, даже если локально его назвали dev-only.
