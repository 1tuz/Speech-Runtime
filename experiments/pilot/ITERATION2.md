# Итерация 2: Veche-bench как контрольный набор

Дата прогонов: 2026-10-28. Машина: Apple M5 Pro, 48 ГБ, macOS 27.0 (26A428),
Python 3.12 (`experiments/.venv`), Swift 6.4. Ни одно число здесь не является
подтверждённым бенчмарком: референсы — сценарный текст, а не результат
прослушивания человеком.

Связанные отчёты: [стриминг и задержки](STREAMING.md), [адаптация к терминам](ADAPTATION.md),
[раннеры и методика](../runners/README.md).

Четыре варианта (`raw`/`simple`/`medium`/`hard`) — одна и та же запись с разной
постобработкой, а не четыре корпуса. Тексты референсов во всех вариантах
совпадают побайтово (проверено сравнением `manifest.tsv`).

## Подготовка

`experiments/corpus/prepare_veche.py` режет встречу по границам реплик CSV,
пишет `manifest.tsv`, `metadata.jsonl` и RTTM. Правила, зафиксированные до прогонов:

- реплики короче 0.35 с отброшены (2 из 1290): Parakeet требует ≥ 0.3 с, и все
  модели должны видеть одинаковый набор;
- `dev` — три встречи (`2-one-to-one`, `5-it-product`, `7-bi-platform`), `test` —
  остальные шесть; разбиение по встречам, потому что реплики одной встречи зависимы;
- `mic_class=phone`, `register=R2`, `noise_class=clean` назначены скриптом и не
  проверены прослушиванием — заглушки для структуры метаданных, а не факты;
- `transcript_status=scenario_text_not_listened`, `rights_status=card_checked_no_human_signoff`:
  поэтому `preflight --benchmark` на наборе сознательно не проходит.

Итог: 1288 сегментов, 7010 с (116.8 мин), test 967 сегментов / 13 982 слова,
dev 321 сегмент, 83 вхождения терминов словаря `terms-v1` (366 терминов,
sha256 `8543fd9a…`).

## Что уже видно

1. **Языковая подсказка `language: .russian` в Parakeet подавляет латиницу.**
   Без подсказки v3 даёт `latin_form_accuracy` 26.7 % против 0.0 %, Ultra — 50.0 %
   против 0.0 %, term recall exact растёт с 9.3 % до 18.6 % (v3) и с 11.6 % до 34.9 %
   (Ultra). WER при этом почти не меняется (6.20 → 6.18; 5.79 → 5.89). Подсказка
   включает script-aware фильтрацию не-кириллических токенов — механизм описан в
   документации FluidAudio.
2. **Whisper лучше всех сохраняет латинские термины** (latin-form 60 %, term recall
   exact 46.5 %), но втрое дороже по времени на коротких репликах (RTF 0.43 против
   0.009 у Parakeet).
3. **GigaAM v3 даёт лучший WER (4.86 %)**, GigaAM Multilingual — лучший CER (1.74 %),
   но обе теряют латиницу: ML-модель CTC-чаровая и пишет всё кириллицей
   (`апи`, `кавка`), v3 смешивает формы (`Beckaind`).
4. **Nemotron 3.5 multilingual даёт 12.24 % WER** на батч-прогоне (тир 2240 мс): деления 564 из 13 982 слов — на порядок больше, чем у остальных. Это согласуется с его стриминговой природой: чанки по 2.24 с теряют межчанковые переходы. Латиница — 0 %.
5. **Qwen3-ASR 0.6B в 8-bit MLX даёт 12.27 % WER** — вдвое хуже остальных, с
   фактическими подменами (`backend → БКМ`, `регрессии → репрессиям`). Гипотеза:
   квантование или windowed-энкодер на коротких репликах. Проверено: fp16-артефакт
   даёт 12.28 % — квантование ни при чём, дело в самой модели на русском.
5. WER 5 % на этом наборе — верхняя оценка качества: текст читается со сценария,
   дикторов 21, шума в `data_simple` нет.

## Контроль на общем русском (FLEURS ru_ru test)

775 записей, 2.5 ч, официальные транскрипты, CC BY 4.0 (`google/fleurs`,
ревизия `70bb2e84…`). Аудио float32 16 кГц — раннер читает его без конвертации.

| Система | WER | CER |
|---|---|---|
| GigaAM v3 `e2e_rnnt` | 4.70 % | 1.66 % |
| Parakeet TDT v3 (без подсказки) | 6.18 % | 2.12 % |

Разрыв между GigaAM и Parakeet на общем русском (1.48 п.п.) и на IT-встречах
(1.32 п.п. на `data_simple`) одного порядка: на этом объёме нельзя утверждать,
что IT-домен меняет соотношение систем. Обе системы деградируют на Veche
относительно FLEURS, но у Parakeet это ноль (6.18 % на обоих наборах), а у
GigaAM — рост с 4.70 % до 4.86 %.

## Диаризация

Offline `DiarizerManager` (VBx) FluidAudio на целых встречах, RTTM сравнивался с
RTTM из CSV (`experiments/runners/der.py`, collar 0.25 с, шаг 10 мс, перекрытия
учитываются):

| 3-auth-incident | 3 | 3 | 33.4 % | 53.1 % | 20.3 с | 0.0 с | 60.0 с |
| 2-one-to-one | 2 | 2 | 36.0 % | 69.8 % | 5.1 с | 0.05 с | 37.6 с |
| 5-it-product | 5 | 5 | 36.8 % | 46.5 % | 15.8 с | 0.01 с | 95.2 с |

| 7-bi-platform | 7 | 4 | 50.8 % | 75.4 % | 36.1 с | 0.23 с | 240.2 с |
| 6-b2b-saas | 6 | 4 | 51.3 % | 74.1 % | 72.0 с | 0.78 с | 443.7 с |
| 9-tech-strategy-meeting | 9 | 4 | 56.9 % | 77.7 % | 40.4 с | 0.74 с | 510.6 с |
| 4-hr-retention | 4 | 3 | 58.3 % | 72.1 % | 107.3 с | 0.11 с | 828.2 с |
| 10-it-meeteing | 10 | 4 | 60.4 % | 84.2 % | 34.9 с | 0.93 с | 245.1 с |

DER 33–60 %, JER 47–84 % при недооценке числа говорящих на многоролевых встречах:
с 5+ ролями кластеризация сливает спикеров, и основная ошибка — confusion, не
пропуски. JER (1 − средний Jaccard по говорящим эталона) считается независимо от
DER и подтверждает ту же картину: лучше всего на встречах с 2–5 ролями, хуже
всего там, где ролей 10, а кластеров 4.

Конфигурация по умолчанию (`clusteringThreshold=0.7`), порог не настраивался.
Перекрытий в `data_simple` нет вообще (0.0 с из 7022 с речи), поэтому «ошибки на
overlap» на этом варианте не измеримы; в `data_medium` и `data_hard` перекрытия
занимают 170.1 с (2.5 % речи) — это и есть материал для отдельного замера.

## Диаризация на варианте с перекрытиями

Тот же offline VBx на `data_medium` (те же встречи и реплики, добавлены
перебивания). Corpus-level DER — по сумме ошибок к сумме длительности речи:

| Вариант | Речь | Перекрытия | DER | JER (среднее) | miss | false alarm | confusion |
|---|---|---|---|---|---|---|---|
| `data_simple` | 6354 с | 0 с | 52.0 % | 69.8 % | 6.2 % | 0.0 % | 45.7 % |
| `data_medium` | 6076 с | 170.1 с | 42.8 % | 57.2 % | 6.2 % | 0.0 % | 36.6 % |
| `data_hard` | 6076 с | 170.1 с | 44.4 % | 64.0 % | 5.5 % | 0.1 % | 38.8 % |

По встречам (`data_medium`):

| Встреча | Ролей | Кластеров | DER | JER |
|---|---|---|---|---|
| 2-one-to-one | 2 | 3 | 6.1 % | 17.5 % |
| 3-auth-incident | 3 | 4 | 18.9 % | 30.6 % |
| 8-sales-meeting | 8 | 6 | 32.8 % | 61.0 % |
| 9-tech-strategy-meeting | 9 | 7 | 36.0 % | 59.2 % |
| 7-bi-platform | 7 | 5 | 38.4 % | 63.7 % |
| 6-b2b-saas | 6 | 5 | 40.7 % | 61.9 % |
| 5-it-product | 5 | 4 | 43.1 % | 66.4 % |
| 10-it-meeteing | 10 | 4 | 55.5 % | 81.8 % |
| 4-hr-retention | 4 | 4 | 58.5 % | 72.9 % |

**Ошибки именно на перекрытиях:** из 170.1 с одновременной речи 141.7 с
размечены неверно — DER на перекрытиях 83.3 % против 42.8 % по всему набору.
Движок не разрешает одновременную речь: он выдаёт один кластер на кадр, поэтому
в перекрытии второй говорящий всегда теряется. Это ограничение метода
(`DiarizerManager`, VBx с одним назначением на кадр), а не настройки.

Шум (`data_hard`) добавляет 1.6 п.п. DER относительно `medium` при тех же
перекрытиях: 42.8 → 44.4 %. То есть на диаризацию влияет в основном не шум, а
число ролей.

**Неожиданное:** DER на `medium` ниже, чем на `simple` (42.8 % против 52.0 %)
при одинаковых сценариях. Разница почти целиком в confusion (36.6 % против
45.7 %), а не в пропусках. Гипотеза — перекрытия дают кластеризации больше
материала для разделения похожих голосов, но это не проверено: варианты
отличаются не только перекрытиями, но и расстановкой пауз. Утверждать, что
«перекрытия улучшают диаризацию», на этом основании нельзя.

## Влияние сложности варианта

Те же встречи и те же тексты референсов, меняется только постобработка аудио
(`raw` → `simple` → `medium` (перекрытия) → `hard` (шум и эффекты)):

| Вариант | Parakeet v3 (без подсказки) | GigaAM v3 |
|---|---|---|
| `data_simple` | 6.18 % | 4.86 % |
| `data_medium` | 7.51 % | 6.89 % |
| `data_hard` | 11.26 % | 8.91 % |

Перекрытия речи добавляют 1.3–2.0 п.п. WER, шум — ещё 2.0–3.8 п.п. При этом сам
объём перекрытий мал: 170.1 с из 6852 с речи (2.5 %), одинаково в `medium` и
`hard` — `hard` отличается от `medium` только шумом. Порядок
систем не меняется, а разрыв между ними немонотонен: 1.3 п.п. на `simple`,
0.6 п.п. на `medium`, 2.4 п.п. на `hard`. То есть перекрытия сближают системы,
шум — разводит; на одной встрече этот разрыв объяснять нечем, объём слишком мал.
Прогонов на `data_raw` нет: он отличается от `simple` только паузами.

## Ограничения

- Референс — сценарный текст; расхождения «как написано» и «как произнесено»
  (числа, латиница, имена) человеком не выверены.
- 83 вхождения терминов на test — слишком мало для терминных выводов; интервал
  шире самого эффекта.
- `data_medium`/`data_hard` ещё не прогнаны.
- Диаризация: один движок, один порог, без сравнения с LS-EEND/Sortformer.
- Whisper шёл с `--language ru`, GigaAM — без языковых подсказок (у пакета их нет);
  это разные условия, и по терминам сравнение несимметрично.
