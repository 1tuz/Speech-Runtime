# Пилот: триаж гипотез без референсов

`review.py` — помощник ручной выверки, а не метрика. На вход идут N≥2 систем гипотез на
одних и тех же сегментах; референсов нет, поэтому инструмент отвечает не «кто точнее», а
«где системы расходятся и какие формы терминов каждая выбрала». Человек читает очередь и
слушает только спорные места.

```bash
python3 experiments/pilot/review.py \
  --systems gigaam=experiments/corpus/local/kubernetes-dev/gigaam-hypotheses.tsv \
  --systems parakeet=experiments/corpus/local/kubernetes-dev/parakeet-hypotheses.tsv \
  --systems whisper=experiments/corpus/local/kubernetes-dev/whisper-hypotheses.tsv \
  --out-dir experiments/corpus/local/kubernetes-dev/pilot-review \
  --terms experiments/asr_eval/terms.json
```

Вход — TSV `<id>\t<текст>`, набор id у всех систем обязан совпадать. Нормализация
(`norm.py`, norm-v2), выравнивание (`align.py`), WER (`wer.py`) и терминология
(`terms.py` + `terms.json`) импортируются из `experiments/asr_eval` по `sys.path`;
логика там не копируется и не меняется. Сети и аудио инструмент не трогает.

## Выход

`review-queue.tsv` — сайты расхождений, по строке на сайт:

| колонка | смысл |
|---|---|
| `segment_id` | id сегмента |
| `position` | номер токена в нормализованном потоке базовой системы, с 1 |
| `context` | ±3 токена базы вокруг сайта, сам сайт в `[квадратных скобках]` |
| `<система>…` | что сказала система на этом участке; `∅` — ничего (удаление/вставка) |
| `n_varying` | число расходящихся систем: все, кто не входит в самую большую группу совпавших; если не совпал никто — все |
| `term` | термин словаря, чьё вхождение попало в сайт (иначе пусто) |

Сортировка: сначала `n_varying` по убыванию, затем вес класса термина (`tools`/`command` 4,
`abbrev` 3, `translit` 2, `wordform`/`number` 1, без термина 0), затем `segment_id`,
`position`. Вес — порядок внимания, а не оценка важности термина для продукта.

`review-summary.json` — `segments`, `system_count`, `systems`, `base_system`, `sha256`
каждого входа и словаря, `pairwise_wer` (по корпусу и по сегментам), `sites`
(всего / с термином / по `n_varying` / по сегментам), `term_forms` (счётчики вердиктов по
системам и таблица форм `exact_latin` / `exact_other` / `translit` / `corrupt` / `miss`).
Инструмент детерминирован: без времени, путей хостов и случайных значений — повторный
запуск на тех же входах даёт побайтово те же файлы.

## WER между системами — это расстояние, а не качество

`pairwise_wer` сравнивает системы друг с другом: у «референса» и «гипотезы» здесь нет
разного статуса. Совпадение систем ничего не доказывает — они могли одинаково ошибиться, а
расхождение не указывает, кто прав. WER пары несимметричен (`a→b` ≠ `b→a`): нормализация
`wer.py` снимает филлеры из гипотезы, но не из референса, поэтому в summary есть оба
направления. Нули и малые значения здесь означают «системы похожи», а не «ошибок нет».

## Как добавить систему

1. Прогнать модель на тех же wav (те же 20-секундные фрагменты, 16 kHz mono) и записать
   `<id>\t<текст>` с теми же id, что у остальных систем.
2. Добавить `--systems имя=путь.tsv`; имя — `[A-Za-z0-9_.-]+`, оно станет колонкой TSV.
3. Не ставить новую систему первой: база выравнивания — первая `--systems`, в её токенах
   записаны `position` и `context`. Смена базы пересчитывает координаты очереди.
4. Пересчитать всё целиком и сравнить `review-summary.json`; числа сравнимы только при
   одинаковых входах, словаре и версии `norm-v2` (хэши есть в summary).

## Ограничения

- Референса нет: точность, recall терминов и «кто прав» не измеряются. Сайт расхождения —
  приглашение послушать фрагмент, а не приговор системе.
- Множественное выравнивание строится через базовую систему: вставки и удаления на
  границах сайтов могут склеиваться в один сайт, а порядок систем влияет на координаты
  сайтов (не на сам факт расхождения).
- Формы терминов ищутся по всему сегменту: позиционного окна ±3, как в `terms.py` на
  референсе, здесь нет. `corrupt` — эвристика `terms.py`; поверх неё отсечены токены,
  совпадающие с формой другого термина, и токены с другой первой буквой, но ложные
  срабатывания остаются (`vector` → `vendor`).
- Словарь `terms.json` неполон для живой речи пилота (`worker node`, `кубернетс` в нём
  нет), поэтому часть расхождений остаётся без термина.
- Нормализация `norm-v2` стирает пунктуацию, регистр и числа; различия в них инструмент не
  показывает.
