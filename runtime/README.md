# Runtime prototype: проверка архитектурных допущений

Экспериментальный прототип, а не продукт. Он существует, чтобы измерить сквозной путь
«HTTP-клиент → демон → воркер → ANE» и стоимость изоляции процессов, а не чтобы зафиксировать API.

Состав:

| Часть | Язык | Роль |
|---|---|---|
| `daemon/` | Swift 6.4 | loopback HTTP API, токен, каталог моделей, сессии клиента, idle-unload, супервизия воркера |
| `worker/` | Rust (`wavo` 0.4) | загрузка GGUF, очереди interactive/batch, earshot VAD, эндпоинтинг, транскрибация |
| `models.json` | — | объявленные модели, пути и backend (`ane`/`gpu`); пути не коммитятся |

Запуск:

```bash
cd runtime/worker && cargo build --release
cd ../daemon && swift build
cp ../worker/target/release/sr-worker .build/debug/sr-worker
.build/debug/speech-runtime --config ../models.json --port 8477 \
  --worker "$PWD/.build/debug/sr-worker"
```

Клиент `sr` говорит только по HTTP, как стороннее приложение:

```bash
sr health
sr load gigaam
sr transcribe file.wav --model gigaam --priority batch
sr stream file.wav --model gigaam --realtime 1   # подача в темпе реального времени
```

## Измерения (2026-11-04, Apple M4, 16 ГБ, macOS 27.2, GigaAM v3 e2e-RNNT Q8_0, ANE)

| Что | Значение | Условие |
|---|---|---|
| Загрузка модели | 45–105 мс | `ane`, тёплый файловый кэш |
| Батч 20.1 с аудио | ASR 76 мс, wall 174 мс, RTF 0.004 | `priority=batch` |
| Стриминг 1×, 12 реплик | WER 5.88 %, CER 1.23 %, 12 финалов | `/tmp/pe_window.wav`, `min_silence_ms=320` |
| Задержка 1×, p50 / p95 | e2e **477 / 489 мс**: тишина 320, очередь 0, ASR 57 / 60, доставка 93 / 123 | от последнего голосового кадра |
| Два стрима + батч, 4 клиента | 4/4 ended, 48 финалов, 36 batch-задач | interactive p95 ASR 31 мс против batch p50 148 мс |
| Две модели одновременно | gigaam e2e 147 / 173 мс, parakeet-ultra 190 / 198 мс | p50 / p95, 12 финалов у каждой |
| Демон | 12 → 380 МиБ RSS | 30 минут повторяемого аудио при 16×, около 117 с реального времени |
| Воркер | 35–42 МБ RSS | после выгрузки 41 МБ RSS |
| Выгрузка модели | возвращает `loaded models: none`; активная сессия получает отказ | память ANE отдельно не измерена |

Прежние **133 мс** — это время от срабатывания эндпоинтера до финала при 4× подаче, а не от
последнего голосового кадра. При 1× к нему добавляется 320 мс ожидания тишины: 477 мс p50 от
последнего кадра, из них 157 мс — ASR и доставка. WER относится только к одному 47-секундному
фрагменту и не является оценкой на полноценном корпусе. Эти измерения не являются бенчмарком продукта.

В ускоренном длительном прогоне RSS демона вырос с 12 000 до 388 784 КиБ; RSS воркера —
с 34 704 до 38 800 КиБ. Причина роста демона не установлена, устойчивость памяти не подтверждена.
Команда: `python3 -m runtime_eval.soak long-session --wav /tmp/pe_window.wav --minutes 30 --speed 16 --json /tmp/soak-long-fixed.json`
из каталога `experiments`. Исходный WAV и JSON локальные, в репозиторий не включены.
Повтор с 5 минутами аудио при 16× и пределом 64 МиБ завершился ошибкой: RSS демона
12 224 → 110 928 КиБ, воркера 35 776 → 38 704 КиБ. На том же процессе 3000 отдельных
запросов `/health` без аудио увеличили RSS с 111 008 до 164 880 КиБ. Это локализует
воспроизведение к пути запросов, но не устанавливает причину роста.

## Что было сломано и исправлено при проверке

Дефекты найдены измерениями, а не чтением кода:

1. `session_open`/`session_audio`/`session_end` не несли `id`, ответы приходили с `id: null`, и демон
   отваливался по таймауту. Идентификаторы теперь возвращаются на всех операциях.
2. `RuntimeClient.streamAudio` отправлял сырой `f32le` без `X-Sample-Format`, демон пытался разобрать
   его как WAV.
3. Метрика «эндпоинт → финал» смешивала аудио-время и wall-clock (при 4× подаче давала −14.9 с).
   Теперь позиция аудио переводится в часы по контрольным точкам подачи.
4. `FileHandle.bytes.lines` на stdout воркера задерживал готовую строку до 30 с на pipe, что давало
   ложные таймауты запросов. Чтение вынесено в отдельный поток с упорядоченной передачей строк.
5. Запись в лог из нескольких задач шла без синхронизации и портила строки.
6. Тесты эндпоинтера кодировали расчёт, несовместимый с кадром 16 мс; переписаны на проверку
   инвариантов (`pcm = (end − start)`, `end = last_voice + post_roll`).

## Проверенные инварианты

| Проверка | Результат |
|---|---|
| Неизвестная модель | `{"error":"unknown model nope; declared models": [...]}`, без подмены |
| Запрос без токена и с неверным токеном | 401 |
| Аудио и транскрипты в логе | не пишутся (проверено поиском по логу) |
| Отмена сессии | `session_cancel` снимает очередь и помечает задачи отменёнными |
| Выгрузка модели | активная сессия получает отказ; после завершения модель выгружается |

Проверены отдельные прогоны четырёх клиентов с batch, двух моделей и аварийного завершения
воркера. Не проверены исчерпание памяти, 30–60 минут реального времени, освобождение всей
памяти после длительной нагрузки и восстановление после сбоя во всех состояниях сессии.

## Ограничения

Прототип не претендует на финальный контракт: имена полей, формат событий и схема конфигурации
выбраны для измерений. Транспорт — loopback HTTP с bearer-токеном; WebSocket, LaunchAgent и
разделение воркеров по движкам не проверялись и не объявляются решением.
